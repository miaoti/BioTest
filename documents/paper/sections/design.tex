\section{Methodology}
\label{sec:design}

\biotest{} treats a parser as an opaque function from bytes to a
structured record set and exercises it via spec-derived metamorphic
relations~\citep{chen1998metamorphic,chen2018metamorphic,segura2016survey},
multi-runner consensus oracles, and coverage-steered corpus
augmentation. The framework remains useful across heterogeneous
parser implementations of the same format without per-SUT
engineering effort beyond the parse-and-emit shim that
coverage-guided fuzzers already require. VCF~\citep{danecek2011vcf}
and SAM~\citep{li2009sam} are partially context-sensitive textual
formats: header declarations constrain record-level types, and
they admit multiple semantically-equivalent surface forms (tag
order, integer encodings, mandatory-vs-default values) that make
them amenable to metamorphic testing.

Figure~\ref{fig:architecture} gives the architectural overview.
The framework is organised as four phases.
\textbf{Phase~A}~(specification ingest) and
\textbf{Phase~B}~(LLM-driven MR mining) run \emph{once per format}
to populate a specification vector store and an admitted-MR
registry. \textbf{Phase~C}~(multi-runner execution and consensus
oracle) and \textbf{Phase~D}~(coverage-driven feedback) run
\emph{per iteration on the SUT pool}. A corpus stack supplies the
inputs that Phase~C consumes, spanning a semantics-preserving
metamorphic tier and a per-iteration augmentation tier that
trades semantic equivalence for branch and value diversity. The subsections that follow describe each component in turn,
with \S\ref{sec:design-corpus} cataloguing the corpus stack.
The matched-protocol setup we use when grading \biotest{}
against coverage-guided fuzzers is described at the start of
the evaluation in \S\ref{sec:evaluation}.

\subsection{Design Constraints}
\label{sec:design-constraints}

\biotest{} is built on three constraints. \textbf{C1:
SUT-agnostic core.} The framework contains no per-SUT logic in
any phase. \textbf{C2: Per-SUT user effort bounded by what
coverage-guided fuzzers already require.} Onboarding a parser is
a thin \emph{harness} that calls the parser and emits a
canonical-JSON record set, plus a $\sim$50-line Python
\emph{runner} subclass that wraps the harness for the
orchestrator. The harness conforms to a fixed per-format
canonical schema (typed fields, deterministic ordering, 1-based
coordinates). \biotest{} adds \emph{no other per-SUT artefact}: no
metamorphic relation, oracle predicate, seed corpus, instrumented
build, bytecode-rewriting agent, or fork-server harness.
\textbf{C3: Semantic-digest oracle.} A violation is declared when
the observable parse outcome (parse-success flag, canonical-JSON
digest, exception class) diverges, with no per-SUT assertion
code. The oracle's intermediate strength forfeits
coverage-feedback's bug-finding advantage on byte-content-lenient
parsers~\citep{klees2018fuzz,boehme2020boosting} in exchange for
portability across four parser languages.

\subsection{Specification Ingest}
\label{sec:design-phase-a}

The published format specification is segmented at rule and
field-definition boundaries, embedded with a sentence-transformer
encoder, and indexed in a vector store for retrieval-augmented
prompting~\citep{lewis2020rag}. The store is parametric over
format and spec version. It runs once per format and is rebuilt
only when the spec version changes, so the cost amortises across
every SUT that targets the same format.

\subsection{LLM-Driven MR Mining}
\label{sec:design-phase-b}

Conditioned on the top-ranked spec chunks retrieved from the
Phase~A store by cosine similarity to the rule a proposal must
cite, an LLM proposes candidate metamorphic relations of the form
$\mathit{out}(\mathit{parse}(x)) \equiv
\mathit{out}(\mathit{parse}(T(x)))$. The model is constrained to
a whitelist of $\sim$20 atomic transforms registered in the
framework. Each candidate MR traverses three sequential admission
gates. (i)~A \emph{whitelist gate} rejects unrecognised
transforms. (ii)~A \emph{hash gate} collapses candidates whose
$(\mathit{format}, \mathit{scope}, \mathit{transform\_steps})$
tuple matches an already-admitted MR, so LLM nondeterminism does
not inflate the registry. (iii)~A \emph{seed-corpus gate}
validates round-trip equality on a hand-curated reference corpus
before admission, and is the load-bearing rejection cause across
recorded snapshots. Phase~B runs once per format and writes its
output to an MR registry that Phase~C consumes.

\subsection{Multi-Runner Execution and Consensus Oracle}
\label{sec:design-phase-c}
\label{sec:design-consensus}

For each input $x$ in the corpus stack and each admitted MR $T$,
Phase~C routes $x$ and $T(x)$ through every configured parser
runner. The VCF runner pool is htsjdk, vcfpy, noodles, and pysam.
The SAM pool is htsjdk, biopython, seqan3, and pysam. When the
SUT under grading is one of these runners, the remaining three
voters supply the consensus. Each runner emits a parsed record
set canonicalised to JSON and hashed, alongside an exception
class on failure.

The oracle classifies the input under three layered
predicates~\citep{mckeeman1998differential}.
(i)~\emph{Differential consensus}: if a strict majority of
runners agrees on a digest $\sigma^\star$ and runner~$i$
disagrees, runner~$i$ is implicated.
(ii)~\emph{Metamorphic consensus}: if
$\sigma^\star_x = \sigma^\star_{T(x)}$ but
$\sigma_i^x \ne \sigma_i^{T(x)}$, runner~$i$ is implicated.
(iii)~\emph{Relation quarantine}: if the consensus disagrees on
$x$ versus $T(x)$, the relation has misclassified what the spec
says is semantics-preserving and is quarantined. The choice
$N\ge 3$ is the minimum that admits a strict majority and
distinguishes ``one runner is wrong'' from ``the spec is
ambiguous''~\citep{barr2015oracle}.

\subsection{Coverage-Driven Feedback}
\label{sec:design-phase-d}

After each iteration of Phase~C, \biotest{} reduces per-language
coverage telemetry to per-class blind-spot tickets and folds the
highest-yield uncovered classes back into Phase~B's prompt as the
next round's mining target. The feedback loop terminates on a
stop criterion (consecutive iterations with no admitted MR or no
uncovered class above a yield threshold) rather than on a fixed
wall-clock tick. This is the only part of the framework that
consumes per-SUT coverage information, and only at the prompt
level.

\subsection{Corpus Stack}
\label{sec:design-corpus}

A pure metamorphic test loop ceilings at modest line coverage on
file-format parsers. We therefore widen the corpus along two
tiers ordered by decreasing semantic preservation.

\textbf{Metamorphic tier.} The metamorphic tier supplies inputs
whose Phase~C outputs the consensus oracle scores under the
metamorphic predicate. Seeds come from LLM-synthesised inputs
targeting uncovered spec rules and from an upstream-derived
corpus of real-world VCF/SAM files. Metamorphic relations are
mined through three additional channels beyond Phase~B's primary
registry: spec-rule-targeted malformed mutators that flip a
single grammar production; a Hypothesis-driven property-based
generator parameterised by the format's canonical schema; and
reflection-discovered API-query relations of the form
$P(\mathit{parse}(x)) \equiv P(\mathit{parse}(T(x)))$ over the
parser's public scalar getters. An opt-in LLM-mined relation
channel and a theme-restricted spec-invariant registry round out
the tier.

\textbf{Augmentation tier.} The augmentation tier trades strict
semantic equivalence for branch and value diversity. Every
transformed input accepted by at least one runner is
content-hashed and deduplicated into a persistent corpus keeper,
so each iteration starts from a strictly larger pool. Value-level
operators perturb spec-bounded numerical fields (POS, QUAL, MAPQ,
AF, DP, TLEN) within validity bounds and emit Boundary Value
Analysis~\citep{myers1979art} variants at the spec extremes.
Byte-level operators apply validity-gated bit-flip,
byte-substitute, byte-insert, and byte-delete on non-header
positions; a lenient companion drops the validity gate for inputs
consumed only by mutation-adequacy grading. A structural
enumerator emits spec-derived branch-diverse inputs (CIGAR-shape
mixes, tag-type permutations, multi-sample records, varied
FILTER/INFO/FORMAT compositions). Augmentation outputs feed
mutation grading and the differential-only oracle, which does not
require metamorphic validity to declare a kill.
